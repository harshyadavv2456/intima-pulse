# Operating notes – Intima Pulse
Static site on GitHub Pages (main, root). Vanilla JS in `assets/app.js` renders `data/*.json`. See `SCHEMA.md`.

## Daily update
1. `git pull --rebase`
2. Edit JSON in `data/` (tester owns issues/journal/features/companion/performance/changelog/accounts/meta; site owner owns social/funding/outlook).
3. `node scripts/validate.js` (checks JSON validity + funding rank scores) — `node scripts/rank.js` recomputes funding `rank_score = value*fit/effort`.
4. `git add -A && git commit -m "daily update YYYY-MM-DD" && git pull --rebase && git push`
Pages redeploys in ~1 min. Page shells are generated by `node scripts/build.js` (only needed if nav/pages change).

## Rules
- Every page has `<meta name="robots" content="noindex">`; robots.txt = Disallow all.
- Synthetic test data only. Never publish vulnerabilities, secrets, PINs, backup codes, real user data.
- Never submit funding applications or create portal accounts from here; drafts are copy-paste text only. Re-verify every deadline on the official page before the draft is used.
- Honest privacy copy: health logs sync to cloud; AI chat goes to a third-party AI provider; consult messages encrypted at rest with operator-held key (not end-to-end). Do not claim more.
- Social quotes: no usernames; always source URL + date. Trend = "insufficient history" until ≥2 snapshots exist.
- Never overwrite tester files; create only if absent.
- Funding items need `url`, `verified_on`, `verified`; unverified = say so; never invent deadlines.

## Outlook page (`outlook.html`, `data/outlook.json`) — site owner file
Valuation scenarios, comps, funding routes, unit-economics calculator, compliance, Pvt Ltd checklist, investor summary, milestones. Live cards (health score, open P0/P1, D30 retention gaps, funding deadlines, social coverage, tester evidence) are computed in the browser from the other data files — never copy those numbers into outlook.json.
**The daily evening run MUST refresh `outlook.json`:**
1. Set `reviewed_on` (YYYY-MM-DD, IST) and `updated` (ISO timestamp); set `reviewed_by`.
2. Update `manual_inputs` (`entity_status`, `dpiit_recognised`, `revenue_inr`, `paying_clinics`, `d30_retention_doctor_referred_pct`, `doctor_referred_users_tracked`) only from real facts the founder has confirmed; leave `null`/0 otherwise. Never invent traction.
3. Re-verify any funding deadline <30 days out in `funding.json` (milestones with `funding_id` follow it); adjust `milestones` dates/status if the plan moved.
4. Add an entry to `changes` (`date`, `by`, `change`) for anything that changed (scenario ranges, comps, milestones, inputs). If nothing changed, add one line saying "reviewed, no change".
5. If the page shows "stale" (reviewed_on older than yesterday) the run was missed.
**Every Sunday:** re-check all `valuation.comps` and `valuation.benchmarks` sources (open the page; note new rounds/valuations; mark `source_opened`, `checked_on`), then set `comps_last_checked` = today and `comps_next_due` = next Sunday. Next due: 2026-10-04.
Rules: every number is labelled SOURCED (page opened + date) vs ESTIMATE vs UNVERIFIED/THIRD-PARTY; undisclosed valuations stay "Not disclosed" (never guess a comp valuation); keep scenario estimates candid, not inflated; privacy wording must match the Honest-privacy rule above; no referral-fee advice that breaches medical ethics (flag for legal review instead).
